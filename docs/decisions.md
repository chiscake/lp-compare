## Задачи

- Генератор `python/lpbench_py/generate.py`; seed = set·10⁷ + class·10⁵ + structure·10⁴ + index; хэш каждого файла в
  `experiments/manifest.csv`. Наборы: `illustrative` (данные автора), `train` (S×20, M×10 на структуру — только подбор
  DLN), `main` (S×100, M×50, L×30, XL×10 на структуру). Наборы не пересекаются по seed.
- Плотные: $A_{ij}\sim U(0.1,1)$, $b_i=\rho_i\sum_jA_{ij}$, $\rho_i\sim U(0.1,0.5)$, $c_j\sim U(1,10)$.
- Разреженные: то же с маской плотности 8 %, у каждого столбца и строки ≥ 1 ненулевой.
- Вырожденные: $A_{ij}\in\{0,1,2\}$ (вероятности 0.4/0.4/0.2), $c_j\in\{1..5\}$; половина строк активна в целой точке
  $\hat x$ с носителем $m/4$, остальные $b_i\in\{v,2v\}$.
- Эталон $f^\star$: HiGHS (scipy `linprog`, `highs-ds`); контроль `highs-ipm` — максимальное расхождение 1.9·10⁻⁹
  (уточнено после прогона, см. «Изменения после основного прогона»).
- Наблюдение: у плотных задач в оптимуме мало продуктов (медиана 3 из 20 для S, 45 из 2000 для XL), поэтому плотные
  задачи «лёгкие» для симплекса; у разреженных и вырожденных носитель больше.

## Методы и параметры (`experiments/params.ini`)

- Все методы получают одну стандартную форму $[A\;I]z=b$, $\min(-c,0)^\top z$; метрики — на исходной задаче.
- Время — Stopwatch вокруг `Solve` (включая внутреннюю предобработку метода: таблицу, стартовую точку IPM,
  редукцию и оценку $L$ у DLN), без чтения файла и стандартизации.
- Симплекс: $\varepsilon_d=\varepsilon_p=10^{-9}$, лимит пивотов $50\cdot(m+n+m)$. Выходящая переменная у обоих правил —
  минимальное отношение, ничьи — наименьший индекс базисной (правило Бланда); правила различаются только входящей.
  Проверено: на примере Била Данциг зацикливается, Бланд — нет.
- IPM: tol $10^{-8}$ (невязки и зазор, 2-нормы), ≤ 100 итераций, доля шага 0.995, приём Райта для пивотов Холецкого.
- DLN: редукция Remark 1.1, граница $\mathbf1^\top z\le\min(\sum_jU_j,\ \gamma\sum_ib_i)$, $M=1.1\times$граница;
  нормировка строк; стоимости в $[0,1]$; $u^0=\alpha_{\max}e^{-\hat c/(2\lambda)}$, $\alpha_{\max}=\min(0.49,1/\sqrt{N})$;
  шаг $\min\{1/(4\lVert g\rVert_\infty),\ \kappa/(5L\lVert u\rVert_\infty^2)\}$; остановка: $\lVert\hat A\hat x-\hat b\rVert/\lVert\hat b\rVert\le10^{-8}$.
- Лимиты итераций DLN (а не время) — основной лимит: результаты (зазор, итерации, статус) воспроизводимы на любом CPU.
  S: 10⁶, M: 3·10⁵, L: 2·10⁴, XL: 5·10³.
- Таймауты (страховка): S 10 с, M 60 с, L 300 с, XL 600 с.
- Повторы: 1 отбрасываемый + 5 замеров; исключения — DLN на M/L/XL и все методы на XL: 1 замер без прогрева
  (длинные прогоны с упором в лимит итераций; разброс времени между повторами мал).

## Подбор гиперпараметров DLN (набор `train`)

Правило, зафиксированное до подбора: среди комбинаций $(\lambda,\kappa)$, где критерий остановки выполнен в ≥ 80 %
задач класса, взять комбинацию с минимальной медианой зазора; если таких нет — минимальная медиана зазора.

- S (60 задач, 10⁶ итераций, сетка $\lambda\in\{0.05,0.02,0.01,0.005,0.003,0.002\}$, $\kappa\in\{1,3,10,30,100\}$):
  выбрано $\lambda=0.005$, $\kappa=30$ (решено 88 %, медиана зазора 1.6·10⁻⁶). $\kappa=100$ хуже (смещение от шага,
  теорема 3.5), $\kappa\le3$ не успевает за 10⁶ итераций.
- M (15 задач, 3·10⁵ итераций, $\lambda\in\{0.02,0.01,0.005,0.003\}$, $\kappa\in\{10,30,100\}$): ни одна комбинация не
  выполнила критерий остановки; минимальная медиана зазора 0.15 при $\lambda=0.003$, $\kappa=30$. Это значение
  используется для M, L, XL (для L/XL обучающего набора нет).
- Иллюстративная задача в подборе не участвовала; при выбранных параметрах ($\kappa=30$) её зазор 0.49, при $\kappa=3$ —
  $<10^{-3}$ (юнит-тест). Это показатель хрупкости метода, а не подгонки.

## Диагностика DLN на M (до основного прогона)

- Траектория: за первые ~10³ шагов слэки перерастают ($\sum s>\sum b$), продукты сжимаются мультипликативно до
  $10^{-58}$ и затем растут со скоростью, пропорциональной уже малой невязке.
- Точное решение регуляризованной задачи (2.8) (двойственная задача, L-BFGS, `docs/theory-and-plan.md` п. 2.4) на
  `train_M_dense_000`: зазор 1.0 при $\lambda\ge0.01$, 4.9·10⁻² при 0.003, 4.4·10⁻³ при 10⁻³, 2.6·10⁻⁶ при 3·10⁻⁴.
  То есть на M сама регуляризация требует $\lambda\lesssim10^{-3}$ — ниже порога обычного DLN в double.
- Масштабирование столбцов ($z_j=U_j\hat z_j$) смещение систематически не уменьшает — не используется.
- Log-domain DLN на M при $\lambda\in\{10^{-3},3\cdot10^{-4},10^{-4}\}$ за 3·10⁶ итераций (≈1 мин): невязка 10⁻², зазор 0.2–0.6.

## Среда облачного прогона

Cursor Cloud VM: Intel Xeon (4 vCPU, AVX2/AVX-512/FMA), 16 ГБ, Ubuntu 24.04, `linux-x64`, `LpIsa=native`
(`Vector<double>.Count = 4`). Субнормальная арифметика в 123 раза медленнее нормальной (`lpbench env`).
Основной прогон и λ-исследование выполнялись параллельно на разных ядрах (`taskset`); абсолютное время
λ-исследования не анализируется, используется только относительное замедление итерации в зоне денормалов внутри
одного прогона. Облачное время — справочное: ВМ разделяет железо; финальные замеры времени — на машине автора.

## Изменения после основного прогона

- **15.10.2026, эталон $f^\star$.** Валидация показала расхождение симплекса с `highs-ds` до 1.9·10⁻⁹ на вырожденных L
  при совпадении Данцига и Бланда до 10⁻¹³. Проверка сертификатов: решение `highs-ds` (допуски HiGHS по умолчанию
  10⁻⁷) нарушает прямую/двойственную допустимость до 7·10⁻⁸, решение `highs-ipm` с crossover — допустимо до 10⁻¹⁴
  с нулевым разрывом двойственности. Решение: допуски HiGHS $10^{-10}$, $f^\star$ — из решения с лучшим
  прямо-двойственным сертификатом (столбцы `fstar_source`, `fstar_cert`; max сертификат 9.3·10⁻¹³; 596 задач — IPM,
  65 — ds). Задачи (хэши) не изменились; `lpanalyze` пересчитывает зазор по текущему манифесту, перезапуск решателей не
  нужен. Итог: симплекс совпадает с эталоном до 2.7·10⁻¹³.
- **15.10.2026, валидация симплекса.** Точность сверяется только на решённых задачах; упор Бланда в лимит пивотов
  (3 задачи L, 20 задач XL) — отдельная строка отчёта, а не ошибка.
- **15.10.2026, XL.** Класс XL прогнан отдельным процессом на свободном ядре (`raw_xl.csv`) параллельно с концом L;
  основной процесс остановлен перед XL, его неполные строки XL удалены из `raw.csv`. Параметры те же.
- **Наблюдение.** Структура «вырожденная» даёт вырожденные пивоты только на S (14–16 %): вырожденность оптимальной
  вершины не проявляется на пути симплекса из базиса слэков. Гипотеза H2 в части доли вырожденных пивотов не
  подтверждена; рост числа пивотов Бланда подтверждён.
- **23.10.2026, рецензия: κ.** Добавлено исследование по κ (`lpbench grid --kappas`, `kappa_study.kappas`, `kappa.md`):
  на S κ=10 даёт зазор ≤10⁻³ у 83 % задач против 76 % при κ=30, но втрое больше итераций; на иллюстративной задаче
  κ=30 даёт зазор 49 %. Значение κ=30 сохранено (выбрано на обучающем наборе до основного прогона; смена потребовала бы
  перепрогона M/L/XL), ограничение указано в статье.
- **23.10.2026, рецензия: лимит пивотов.** Лимит равен 50·(m+(m+n)) = 50(2m+n), так как столбцов стандартной формы m+n+m
  по числу строк и столбцов; в статье исправлено с 50(m+n). Код и результаты не менялись.
- **23.10.2026, рецензия: `main_M_degenerate_000`.** Независимая numpy-реализация давала 129 пивотов (Данциг) против
  102 в C#. Причина найдена: C# умножает ведущую строку на обратный элемент, обнуляет ведущий столбец точно и
  пропускает нулевые множители; при тех же приёмах numpy даёт 102 при любом допуске ничьих (0…1e-6). Это не платформенный эффект.
